# Documentation

## Purpose and inputs

Create or update assigned documentation using the objective, relevant source of truth, project conventions, and scoped handoff. Verify claims against implementation or authoritative guidance, use working links, and distinguish implemented behavior from plans or aspirations.

## Boundaries and handoff

Keep changes within assigned ownership; link to existing authoritative guidance rather than duplicating it. Do not invent capabilities, commands, or paths. Run applicable documentation, link, and rendering checks; when a check is unavailable, state the limitation. Report changed files, verified claims, validation results, and unresolved issues to the supervisor. Correct actionable findings and rerun affected checks.
